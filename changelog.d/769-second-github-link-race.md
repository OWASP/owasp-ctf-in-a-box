- **Security: a player can no longer swap their GitHub link by racing two link flows (#769).** The one-link rule is now also checked when a profile link's GitHub callback completes, not only when the link starts: the callback is refused with `GITHUB_ALREADY_LINKED` when the player already has a link or any other GitHub account on their kit account. Callbacks that complete at the same moment are decided one at a time through a short claim in `ctf:link:pending:<player id>`, released as soon as the account is written; the account write itself is fenced on that claim, so a callback that stalls past it writes nothing. A player who opens *Link GitHub account* in two tabs with two GitHub accounts ends up with exactly one link and one GitHub account, and no link key moves. A player whose link was refused because another player holds that GitHub login can retry with the same GitHub account, but not link a different one until an organizer unlinks the first. GitHub sign-in is unchanged: a player who renames their GitHub account keeps following the rename. Nothing to do on upgrade; a player stuck after a refused link needs **Unlink GitHub** in Support.
