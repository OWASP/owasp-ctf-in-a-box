- **Fixed: a deleted player's in-flight Secure Development score can no longer restore their solves (#775).** Deleting a contestant now puts the player's scores on hold (`ctf:score-hold:<id>`) before it clears them, and the scorer checks that hold atomically with the solve write: a score posted while the delete runs gets a retryable `503`, and one posted after it gets a final `422` (`player-deleted`) that sync logs as `refused`. The account goes before the progress, so a delete that fails before the account is gone keeps the player's progress and held scores. Sync now sends the scorer the GitHub login it resolved each score through, and the scorer writes the solve only while that login still links to the player (a retryable `503` otherwise), so a score resolved before an unlink, a delete or Delete all accounts and sent after it is resolved again instead of written to the old player. A delete that fails partway lifts its hold on the player's scores (only its own token); run it again to finish it. If the cleanup itself failed, the scores stay held until the delete is run again.
