- **Fixed: a Secure Development verdict judged while frozen, before the scoring start or before a master reset no longer counts after a later comment edit (#821).** sync scored a PR by its score comment's last edit time, and the scoring workflow also edits that comment without judging when a push lands inside the re-run cooldown, so the old verdict was re-dated into a live window and counted. The judge now writes the verdict's own time (`judgedAt`) into the score marker, and sync times the score by it: the freeze, the scoring window and the master-reset epoch are judged at the time the PR was actually judged. A solve now keeps its earliest time whatever order verdicts arrive in, instead of the first one written. A marker without `judgedAt`, from an older judge image, keeps the comment's time. To pick it up, upgrade the box (sync and the scorer service) and rebuild the scorer image from this release, then publish it where the forks pull it from: build and push your `SCORE_IMAGE` (`docs/scorer.md`), then run `ctf-setup.sh org`, which mirrors that image into the event org. The fork workflow file does not change.
